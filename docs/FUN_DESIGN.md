# 재미 개선 설계 메모 — 2026-11-12

[플레이테스트 기록](PLAYTEST_2026-11-12.md)이 버그·밸런스·UX를 다뤘다면, 이 문서는 "왜 덜 재미있는가"와 그 개선 방향을 다룬다. 다른 작업자가 이어받을 수 있도록 결정 사항, 근거, 작업 규칙을 함께 적는다.

- 상태: 후속으로 추가한 8~11번은 구현했다([CAREER_V7.md](CAREER_V7.md)의 "재미 보강" 절). 처음의 방향 7개 중 **1번은 구현했다. 상대 팀 판정에 대한 효과는 확인됐고 우리 팀 쪽 효과와 판정의 승패 영향은 목표에 못 미친다**([PRESSURE_CHOICES_DESIGN.md](PRESSURE_CHOICES_DESIGN.md) 상단의 구현 상태 참고). 나머지 6개는 아이디어 단계다.
- 근거: 한 시즌 플레이(9경기)와 엔진 시뮬레이션. 유사 게임은 작성자의 사전 지식으로 참고했고 별도 조사는 하지 않았다. 아래 제안은 검증 전 가설이다.

## 1. 지금 재미가 빠지는 지점

| 문제 | 플레이에서 관찰한 것 |
| --- | --- |
| 정답이 보이는 선택 | 추천 전략을 누르면 끝. 경기 후 보상은 항상 비싼 유물. 스폰서는 사실상 하나. |
| 잃을 것이 없음 | "로그라이크"를 표방하지만 런이 끝나지 않는다. 주전 3명이 탈진인데도 44–11로 이겼고 CR은 4,972까지 쌓였다. |
| 카드가 숫자 4개 | 3,835장이 능력치와 특성으로만 구분된다. 실제 기록은 "출전 기록 확인"에 묻혀 있다. |
| 독창적인 시스템을 구경만 함 | 압박·각성 판정은 자동으로 일어나고 감독의 선택과 연결되지 않는다. |
| 조합이 의미 없음 | 드래프트는 숙련도 높은 챔피언을 고르는 일이고 조합의 성격이 경기에 드러나지 않는다. |
| 전술 선택이 반복됨 | 경기당 약 11번, 거의 같은 4지선다(승부 / 시야 / 성장 / 후퇴)가 나온다. 보상이 작아 무엇을 골라도 차이를 느끼기 어렵다. |

이 게임만 가진 자산은 두 가지다. **실제 출전 기록**(선수 × 연도 카드, 출전 수, 주력 챔피언, 옛 동료)과 **커리어 고점·저점 위의 압박·각성 시스템**이다. 개선안은 이 둘을 플레이어의 선택으로 끌어오는 것을 기준으로 골랐다.

### 결정 기록

- **작전 타임은 쓰지 않는다(2026-11-12, 사용자 결정).** 처음에는 "경기당 3회의 작전 타임을 판정 대기 선수에게 쓴다"는 안이었다. 새 조작을 추가하는 대신 **기존 전술 선택지에 압박 증감을 넣고, 그 수치를 플레이어에게 보여주지 않는** 방식으로 바꿨다.
- 독창성 기준: 다른 게임의 시스템을 옮기지 않고, 참고는 문제 해결 방식에 한정한다. 실제 기록과 압박·각성을 중심에 둔다.

## 3. 선행 조건과 위험

- **난이도**: 1번과 4번은 "질 수도 있다"가 성립해야 의미가 있다. 첫 리그가 너무 쉽다는 문제(플레이테스트 B4)가 남아 있다.
- **각성의 영향력**: 현재 각성은 승패에 거의 영향을 주지 못하는 것으로 보인다(아래 측정). 1번은 이것부터 확인해야 한다.
- **실존 선수 표현**: 압박에 "무너지는" 연출이 실제 선수에 대한 평가처럼 읽히지 않도록 게임용 추정치라는 틀을 유지한다.
- **세이브**: 경기 규칙을 바꾸면 기존 7.0 세이브가 재생되지 않는다. 7.0은 미배포 상태라 엔진 버전을 올리지 않기로 했다(2026-11-12, 사용자 결정). 배포 이후에는 이 방침을 다시 정해야 한다.

## 5. 이어받는 사람을 위한 작업 규칙

**엔진 구조**

- 경기 규칙은 `web/engine.py`의 `Match`가 여러 규칙 클래스를 상속해 합성한다. 새 규칙은 별도 모듈의 클래스로 만들고 상속 순서에 끼워 넣는다(예: `web/siege.py`, `web/teamfight.py`, `web/clutch.py`).
- **`web/combat.py`, `battlefield.py`, `match_features.py`, `combos.py`, `summoners.py`는 직접 고치지 않는다.** 5.0/6.0 세이브를 재생하는 동결 엔진(`legacy_engine_v5.py`, `legacy_engine_v6.py`)이 이 파일들을 그대로 쓴다. 7.0 전용 변경은 `clutch.py`, `siege.py`, `teamfight.py` 또는 새 모듈에 둔다.
- 새 Python 모듈은 `web/worker.js`의 로드 목록과 `scripts/build_site.py`의 `PYTHON_FILES`에 등록해야 브라우저에서 동작한다.
- 모든 난수는 `self.rng`만 쓴다. 같은 시드와 같은 명령이면 결과가 같아야 한다. 저장되지 않는 임시 플래그는 한 번의 호출 안에서만 쓴다.
- 전술 사건은 블루 팀(플레이어, side 0)에만 생긴다. `Match.simulate()`는 블루 팀의 선택지를 무작위로 고른다. 선택지에 효과를 추가하면 AI 대 AI 경기의 진영 균형이 달라질 수 있으니 블루 승률을 확인한다.

**검증**

```powershell
python -m unittest discover -s tests
node --check web/app.js
node --check web/worker.js
python scripts/build_site.py
```

- 테스트는 `discover`로 실행한다(`python -m unittest tests.test_x`는 모듈 경로 문제로 실패한다). 현재 187개, 1~2분.
- 분포 측정은 `tests/test_management.py`의 `game()`으로 게임을 만들고 `g.units(g.random_roster(목표 OVR))` 두 팀으로 `Match(blue, red, seed, g.champions).simulate()`를 반복한다. 결과는 `m.s`의 `time`, `kills`, `gold`, `clutch_moments`, `decisions`, `highlights`(최근 80개만 보관)와 선수별 `kills`·`deaths`·`pressure`에서 읽는다. 조건당 80경기 이상, 진영을 교대해 돌린다.
- 브라우저 확인은 `.claude/launch.json`의 `nexus` 설정(`python scripts/serve.py --port 8123`)으로 띄운다. 새 게임에서 한 경기를 끝까지 돌려 본다.
- 규칙 수치와 측정 결과는 [CAREER_V7.md](CAREER_V7.md)에 누적한다.

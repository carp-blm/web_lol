# 정적 배포와 코드 노출

GitHub Pages에서 실행하는 Python·JavaScript는 이용자의 브라우저에 전달됩니다. 따라서 소스의 완전한 은닉이나 변조 방지는 불가능합니다. 공개 GitHub 저장소의 원본 코드도 공개됩니다. 저장소 공개 범위는 이 작업에서 변경하지 않습니다.

`scripts/build_site.py`는 실행에 필요한 파일만 허용합니다. Python은 AST를 통해 주석·문서 문자열을 제거한 후 재현 가능한 `runtime.zip`으로 압축합니다. 생산 배포에서 개별 `.py` 파일은 제공하지 않습니다. Worker는 SHA-256을 확인하고 Pyodide 가상 파일 시스템에서 압축을 풉니다. 압축은 노출량과 전송량을 줄일 뿐 암호화가 아니며 복원 가능합니다. 해시 역시 HTTPS와 신뢰할 수 있는 배포물 전달을 대체하지 않습니다.

배포 폴더에는 프런트엔드 4개 파일, 런타임 ZIP, 정적 데이터 3개 JSON, 앱의 대체 이미지 및 승인된 이미지, `.nojekyll`만 허용합니다. 원본 CSV·상세 설명 캐시·배치 도구·테스트·문서·Git 메타데이터·환경 파일·소스맵은 복사하지 않습니다. 기존 `dist`에 알 수 없는 파일이 있으면 게시용 빌드를 실패시킵니다. API 키나 서버 비밀값은 없습니다.

HTML의 Content Security Policy는 스크립트를 동일 출처와 고정 Pyodide 경로에 제한하고, WebAssembly 실행만 허용합니다. 인라인 JavaScript와 문자열 JavaScript 평가, 플러그인, 폼 전송을 허용하지 않습니다. 동적인 상태 막대 때문에 인라인 CSS는 허용합니다. 외부 이미지는 Riot Data Dragon, 폰트는 Google Fonts로 제한합니다. 외부 콘텐츠와 저장값은 HTML 이스케이프 후 표시하며 Python 세이브는 JSON과 허용 명령만 해석합니다. pickle/eval은 사용하지 않습니다.

CDN은 고정 버전이지만 최초 로딩에 네트워크가 필요합니다. 브라우저 로컬 저장은 해당 기기/출처의 저장소이며 인증·서버 권한 경계가 아닙니다. 세이브 입력 상한과 트랜잭션 방식 불러오기로 잘못된 파일이 현재 게임을 덮어쓰지 않도록 합니다.

생산 빌드의 JS·CSS·Worker·ZIP 참조에는 파일 내용에 따른 버전을 붙입니다. 엔진을 갱신하면 Worker를 가져오는 앱 주소도 함께 바뀌어, 브라우저에 남은 구버전 Worker와 새 ZIP이 섞이지 않도록 합니다.

자료 접근 및 공개 배포의 기존 승인 설정은 유지합니다. `PUBLIC_RELEASE_APPROVED`가 활성화된 저장소에서만 Pages 게시가 실행됩니다.
